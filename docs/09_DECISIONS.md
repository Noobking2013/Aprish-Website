Order of authority when two docs conflict: **09 (this file)**, then the more specific doc (06 beats 02 for anything inside the phone, 04 for the wall, 05 for transitions), then everything else. Ask the founder only when the answer changes what the site claims.

| D8 | Each script tab shows a status chip from `status.ts`. Any demo depicting a feature with `confirmed: false` carries its chip. | The demo otherwise shows unconfirmed features as working. |
| D9 | Phone bezel uses the `teal-950` token, not `#102d2d`. QR sits in a cream card with explicit width/height. | Single-sourced palette; no bare white square; no layout shift. |
| D10 | The wall's entrance must **never** tween a card: the requestAnimationFrame loop owns every card's `transform`, `opacity` and `zIndex` each frame, so `gsap.from`/`gsap.to` on cards would fight it. Tween **one scalar** `intro` from 0 to 1 (about 1.1s, `power3.out`) with GSAP and have the loop derive each card's local progress from it. It applies to the **first batch only** (the cards mounted on the first frame); cards that mount later use progress 1. | Overrides doc 04's "stagger ~0.012s" reading. Two writers on one property is the bug class this whole design exists to avoid, and a single scalar keeps the stagger smooth without per-card tweens. |
| D11 | While the detail is open the loop **stops writing card styles** and the stage gets `data-frozen="true"`, which turns off the wall cards' own `backdrop-filter` in CSS so only the overlay's blur is active. The camera ignores wheel, drag, keys and idle drift, and opening **settles** it (`target := cam`, velocity 0) while closing **restarts the idle-drift timer** — the loop is frozen, not stepped, so a target left ahead of the camera would otherwise glide on during the return leg, and a stale input timestamp would otherwise start drift on the first frame after the panel lands. The dialog sits **below** the menu and the stairs. | Freezing gives the flight a still surface to fly out of and back into, and dropping ~20 card blurs while a full-screen blur is on screen is what keeps the open at 60fps. Closing the detail first is what keeps Escape and Tab unambiguous. |
| D12 | The flight uses **fixed** `x`/`y`/`width`/`height` with `CustomEase.create("hop", "0.9,0,0.1,1")` — never an animated `height: auto` (height is measured once, then tweened as a number). If the card is gone or the viewport was resized, the dialog closes with a plain fade instead of the flight. | The wall is inside `#route-root`, which carries a `transform` during the page enter (docs/05), so `position: fixed` inside it would be positioned against that ancestor, not the viewport — the portal escapes it. Animating `height: auto` is not interpolatable and would snap. |
| D13 | The Flow section's progress underline **is** its clock: one CSS animation (`flow-fill` over `--flow-step-ms` = 6000ms) on the active pill's bar, and the bar's own `animationend` advances the step. `useFlowTabs` owns two attributes — `data-armed` (true only after the row has been in view; false for good once the reader takes over, and false from the first render under reduced motion) and `data-paused` (hovered, focused or off-screen). Pausing is `animation-play-state`, so the bar freezes and resumes where it was. Auto-advance stops at 05, Back/Next clamp and `disabled` at the ends, and the pills are a real tablist (roving focus, arrow keys) with the status chip in the **tabpanel**, never on a pill. Every panel is rendered and the inactive ones are `hidden`. | docs/02 §3 asks for a 6s auto-advance with a progress underline; driving the advance from the animation's own end gives the clock one writer, so the bar and the six seconds cannot drift, and `animation-play-state` gives exact pause/resume for free. The global reduced-motion rule forces every animation to 0.001ms, which would otherwise fire `animationend` instantly and race through all five steps — hence the belt-and-braces `animation: none !important` on `.flow-bar` in that same media query, on top of the hook never arming. Rendering all five panels keeps every step's copy in the static HTML (no JS needed, and the copy check can see it). |
| D14 | The safety model's connector line and peach pulse are `lg`-only; below that the nodes wrap and a left-to-right pulse would be untrue. The pulse is one GSAP timeline — 3 × 0.75s hops + a 0.15s fade = 2.4s — built once, started by a single-shot `IntersectionObserver`, killed by `useGSAP`'s cleanup. Travel is a `transform` measured once from the track width (never `left`), and the dot is centred with `margin` so GSAP is the only writer of its transform. Under reduced motion no timeline is built and the dot stays at `opacity: 0`. The four nodes sit on a gapless 4-column grid, so the column centres are exactly 12.5/37.5/62.5/87.5%, which is what lets the pulse be positioned in percentages and still land on each node. In the same pass the Problem card icons render `teal-700`, not the `coral-600` docs/02 §2 originally recorded. | coral-600 on the tint fills measures about 2.5:1, under the 3:1 a non-text graphic needs, so docs/02 §2 was corrected to match. Percentages instead of measured node refs keep the animation independent of font loading and reflow, and measuring once means a resize cannot leave the dot tweening to a stale distance. |
| D15 | The ROI calculator is honest arithmetic (docs/02 §7). `computeRoi` returns `breakEvenVisits = max(0, ceil(planPrice / avgFee − 1e−9))` — the epsilon keeps ₹3,000 ÷ ₹500 at **6** (not 7) and ₹3,001 ÷ ₹500 at **7** — and returns `null`, never `Infinity`, when the fee is 0; the UI then shows `ROI.zeroFeePrompt` in place of the number. The four fields are `type="text"` with `inputMode="decimal"`, parsed by `parseNumber` (commas and spaces stripped, empty = 0, anything non-numeric or over 10,000,000 is invalid and shows `ROI.invalid` after the first blur); an invalid field feeds **0** into the maths, so a result can never render `NaN`. The Home wall teaser is a **static** snapshot of the wall at a fixed 1440×900 board: it reuses `cellCenter`+`lens` and the wall's own `BookingCardContent`, positions six cards in **percentages** of the board with the lens `scale` on a `translate(-50%,-50%) scale(...)`, puts `aria-hidden` on the whole grid, and gives the two centre cards real `.glass` and the rest `.glass--lite`. No measuring, no frame loop. | Division by zero and float error are the two ways "just arithmetic" turns into a visible bug; the epsilon treats float noise as exact without letting a genuine remainder round down. Text inputs stop the browser silently discarding a half-typed value the way `type="number"` does. Because the teaser is a pure proportional scale of the wall's proven layout it cannot overlap at any width, and reusing the wall's card + geometry is what stops the preview drifting from `/live`. |
| D16 | The Home beta CTA (docs/02 §8) renders the full working form inline on the peach-400 band, with the form itself on a `cream-50` card so its `coral-700` error text keeps the 4.9:1 contrast the palette guarantees. The honesty rule is a four-state machine in `src/lib/beta.ts`, not component branches: `submitBeta` returns `ok` **only** for a real `res.ok`, `error` for any non-2xx or a thrown request, `whatsapp` (carrying the prefilled `waLink(buildMessage(...))`) when `FORM_ENDPOINT` is empty, and `bot` when the honeypot is filled — and `bot` is dropped in **silence**: no request, no success, no error. `fetch` and `waLink` are **injected**, so the module imports no DOM and never reads `import.meta.env`, which is what lets `scripts/beta.check.ts` drive every branch with a mocked fetch. The honeypot is a plain off-screen `name="company_website"` field (`tabIndex={-1}`, `autoComplete="off"`, `aria-hidden`). | The one claim a lead form must never break is "we have your details". Making the states a pure function means no component branch can show `BETA.success` on a 500 or an offline error, and the check proves it by asserting that only the 2xx path ever returns `ok` — the idle markup in `sections.check.ts` must contain no success copy at all. The honeypot stays silent on a hit so a bot gets no signal that it was caught (a fake "thanks" would be both a lie and a giveaway). The form lives in `src/features/beta/` rather than under `home/` because `/join` reuses it in Phase 6. |
| D17 | Phase 6 routes. `/product` shows `PRODUCT.h1`, a two-column `MODULES` grid (each entry a `FeatureKey` + a one-line blurb carrying its real status chip) plus one full-width row for the in-development dashboard, then imports the **same** `Safety` and `RoiCalculator` components Home uses. The pricing band (the three deck tiers + `PRICING.note`) renders **only** when `SITE.showPricing` is true, which is false in this build, so the page ships with no price on it. `/black` is full-viewport teal-900 with `wing-motif.png` at 6% and an SVG `gold-500` ring that draws itself once with GSAP (drawn complete, and not animated, under reduced motion); `BLACK.h2` becomes the page's single `<h1 id="route-title">`. `/join` puts the shared `BetaForm` beside the WhatsApp QR and a names-and-roles-only team block (`SITE.founder` / `SITE.spokesperson`). `/privacy` is an honest stub with a source comment flagging the DPDP review and a contact line that falls back to `PRIVACY_NOTICE.contactFallback` while `SITE.contactEmail` is empty. | The safety story and the arithmetic must be the literal same modules on Home and `/product`, or the two pages drift. Gating pricing behind a config flag keeps an unconfirmed deck price list off the site without deleting the work. Every chip still comes from `FEATURES` via `chipFor`, and `scripts/routes.check.ts` audits every rendered text node against `src/content/*`, so a route cannot quietly invent a claim, a price or a criterion. |

| D18 | Phase 7. `scripts/qa.check.ts` (run by `npm run check`) enforces the decidable half of docs/08: forbidden-term and retired-K72 scans, a "no hard-coded status label outside `status.ts`" scan, a `public/**` PNG size audit (≤100KB), the `index.html` head/SEO tags, and per-route heading structure (exactly one `<h1>`, no skipped level) rendered through `renderToStaticMarkup`. Three fixes came out of it. (1) `index.html` gained `og:site_name`/`og:locale`/`og:url`, and the canonical + `og:url` are now written **per route at runtime** by `useDocumentMeta` from `window.location.origin + window.location.pathname` — a root-relative `<link rel="canonical" href="/">` made Vite try to bundle the site root as an asset (EISDIR), and an absolute `SITE.url` is still the placeholder, so the live origin is the only self-consistent source until the domain exists. (2) `wing-motif.png` (1200→800px) and `logo-on-dark.png` (804→200px; it only ever renders at `h-4`) were resized under the limit. (3) the wall card's `aria-label` was **removed**: re-wording the card dropped its visible "via WhatsApp" and booking-id strings, tripping WCAG 2.5.3 (Label in Name); the button's accessible name is now its own visible text plus a visually-hidden "Sample data." suffix (docs/04 updated to match). Two contrast bugs were also fixed: the `Flow` tab numerals lost their `opacity-70`, and the emphasised `Safety` node's sub-text went `teal-700`→`teal-900` over the peach fill. | The checklist is only worth having if it stays true; a script that fails `npm run check` is the only thing that keeps the forbidden-term / status-label / headedness rules from rotting, and it caught the canonical gap and the two oversized PNGs. Lighthouse mobile is now Perf 91-97 with A11y/BP/SEO 100 on all six routes, and there is no horizontal overflow at 360-2560. |
